# Memory in World Models

**A categorized index of papers on memory in world models**

[简体中文](README_cn.md)

</div>

Embodied world models have to remember what they have already seen: a room the camera left a minute ago, an object that went out of view, a step of a task that is already done. This repository organizes papers on how that memory is represented, maintained, learned and evaluated, and how it is built into video, action, navigation and driving world models. The first four top-level categories follow the analysis in the survey [The Past Frames the Future: Memory for Autoregressive Video Generation](https://arxiv.org/abs/2609.28466); the fifth groups work by the kind of world model. It currently lists 308 papers and 13 surveys.

## Scope

The list covers work since October 2024 (a few earlier papers already listed are kept). Each paper is judged on three tags, by what it actually does rather than what it calls itself:

- **Memory**: the problem or contribution is about letting information acquired earlier, and no longer in view, shape later predictions: long-horizon and revisit consistency, selecting and compressing history, persistent state, out-of-view state, and training or evaluating memory. Papers without memory are not listed.
- **World model**: predicts the future of a visual or physical environment from controls such as actions, camera trajectories, navigation commands, ego trajectories or game inputs, and can be rolled out step by step.
- **Embodied**: falls within embodied AI, where the agent may be a robot or a person: manipulation, navigation, driving, egocentric video and hand-object interaction. Games and free camera fly-throughs do not count. Embodied implies world model.

Visual generation work that has memory but is not a world model (long video generation, for example) is listed only when at least two world-model papers in the list cite it. A few core foundation models are also kept for each application and marked "Base".

## Papers by Category

The Tags column shows the three tags above. Each paper has one primary category. World models built for a specific task (world action, navigation, driving, or embodied video models) go under Memory Applications even when their contribution is a memory mechanism. Other categories a paper touches are listed as "Related" after its TL;DR. A paper ID is the category code plus a number: `[MR.Visual.2]` belongs to `MR.Visual` (Visual Memory), and a category without subcategories uses its top-level code, as in `[ME.3]`. Numbers only identify papers and say nothing about quality.
